# Previous review (2026-11-10): what was already found

Written so a later, independent reviewer does not repeat it. It is a record of *findings*, not a verdict to defer to.

## Fixed since (commit `47b1841` and later)
- HomeKit/ecobee: chunked HTTP replies were rejected; a dead idle connection failed the first command instead of reconnecting; the "different key" flag never cleared on re-pair; a thermostat that forgot us was reported as a wrong setup code.
- `LiveScreens.kt` (1,247 lines) was split into four files. `LanHome.kt` (about 850 lines, many responsibilities, shared private state) was deliberately NOT split.
- The rules in `CLAUDE.md` about Jazzer fuzzing and Windows Hello were reworded to match reality (mutation-tested parsers; PIN on Windows).
- A first-run panel, a Ctrl+K command bar, quiet hours, history graphs, an Automations screen and a motion system were added.

## Still true at that date
- No adapter has ever run against a real device. Every adapter is tested only against simulators written by the same author from the same protocol notes, so shared misunderstandings pass.
- Hand-written X25519/Ed25519/SRP-6a (BigInteger, not constant-time), tested against RFC vectors and the JDK; no outside review.
- UI and Android code are compiled and screenshot-tested only in CI; never run by the author.
- Documentation sprawl (about 17 files and 12 ADRs for one owner), some stale.
- Setup is the weakest experience: Tuya needs a developer account and a Python tool for the local key; the ecobee must be removed from Apple Home first; camera video on Windows needs the owner to supply `ffmpeg.exe`.
- A permission change (foreground service, notifications) was made to `CLAUDE.md` and CI before the owner approved it (approved afterwards).
- One Tuya contract test failed once on timing and passed on rerun (possible flake).
- Everything lives on branch `ci/verification-bootstrap`; `main` is the Phase 0 baseline; no pull request or outside review has happened (the author's GitHub token could not create one).

## Judgement then (to be challenged, not trusted)
Strong adapter discipline and privacy architecture; over-built relative to what is proven; the next best step was real-hardware testing, a feature freeze, a first-run flow, and a pull request.
